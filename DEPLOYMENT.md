# Deployment

Two-host deployment: the dashboard (`cmd/server`) and crawler (`cmd/crawler`) run as separate containers on separate machines, built as separate images by `.gitlab-ci.yml` (`Dockerfile`'s `server`/`crawler` targets — see CLAUDE.md's Docker section). This doc covers getting both running, the private link between them, and the public-facing HTTPS in front of the dashboard.

Current staging hosts:

| Role | IP | Domain |
|---|---|---|
| Dashboard (`cmd/server`) | `192.168.88.46` | `citadel-stg.mcmc.gov.my` |
| Crawler (`cmd/crawler`) | `192.168.88.35` | `citadel-api.mcmc.gov.my` |

Images: `nssti-dev.mcmc.gov.my/nsrd/dns-compliance/server:main` and `.../crawler:main`.

## Two separate TLS concerns — don't conflate them

This deployment has **two independent certificates for two independent links**:

1. **Public HTTPS** (browsers/auditors → dashboard) — terminated by Traefik in front of the dashboard host, using the org's own issued certificate. Nothing to generate here — see "Public HTTPS (Traefik)" below.
2. **Private mTLS** (dashboard ↔ crawler gRPC link, ports `50051`/`50052`) — a project-private CA generated by `scripts/gen-mtls-certs.sh`, trusted only by these two binaries. The org cert can't be reused here: this link authenticates two Go processes to each other (not a browser to a server), needs both `serverAuth` and `clientAuth` on both ends, and gRPC's `RequireAndVerifyClientCert` needs a CA that signed both peers. See "Internal gRPC link (mTLS)" below.

Traefik does **not** sit in front of the gRPC link — that connection is direct, host-to-host, authenticated by its own mTLS + a shared token. Putting a reverse proxy in the middle would terminate the mTLS handshake Traefik has no client cert for.

## Internal gRPC link (mTLS)

Generate the CA + one leaf cert per binary, once, with SANs covering both the domain and the IP of each host so either addressing style verifies:

```bash
./scripts/gen-mtls-certs.sh citadel-stg.mcmc.gov.my citadel-api.mcmc.gov.my 192.168.88.46 192.168.88.35
```

Produces `certs/ca.{crt,key}`, `certs/server.{crt,key}`, `certs/crawler.{crt,key}`.

Distribute — each host gets only what it needs, `ca.key` stays offline (only needed to sign further leafs later, e.g. adding a peer or rotating):

| File | Dashboard (`192.168.88.46`) | Crawler (`192.168.88.35`) |
|---|---|---|
| `ca.crt` | required | required |
| `ca.key` | — keep offline | — keep offline |
| `server.crt` / `server.key` | required | — |
| `crawler.crt` / `crawler.key` | — | required |

```bash
scp certs/ca.crt certs/server.crt certs/server.key   user@192.168.88.46:/opt/dns-compliance/certs/
scp certs/ca.crt certs/crawler.crt certs/crawler.key user@192.168.88.35:/opt/dns-compliance/certs/
```

Both binaries take `--tls-cert`/`--tls-key`/`--tls-ca` (or `TLS_CERT`/`TLS_KEY`/`TLS_CA` env vars) — all three or none; a partial set is a startup error (`internal/grpcauth/tls.go`). With all three set, both directions of the link (`Submit` crawler→dashboard, `StartSweep` dashboard→crawler) are mutually authenticated. The `CRAWLER_TOKEN`/`--auth-token` check stays on top of this — TLS and the token are independent layers, both required.

Startup log confirms it took: no `WARNING: gRPC links are unencrypted` line from either binary.

Cert validity is 10 years, no rotation automation — proportionate for a two-peer private link (see the `ponytail:` comment in the script). Re-run the script (with the same or updated host list) and redistribute if that ever needs to change.

## Public HTTPS (Traefik)

The dashboard binary only serves the REST API on `:8080` — it does **not** serve the frontend (`web/dist/`) itself (see CLAUDE.md's Docker section and `web/CLAUDE.md`). Traefik in front of the dashboard host needs to route two things under `citadel-stg.mcmc.gov.my`:

- `/api/*` → the `server` container's `:8080`
- everything else → the built frontend's static files

Using the org's own cert (not ACME/Let's Encrypt) via Traefik's file provider:

```yaml
# traefik/dynamic.yml — file-provider TLS store pointing at the org cert
tls:
  certificates:
    - certFile: /certs/citadel-stg.mcmc.gov.my.crt
      keyFile: /certs/citadel-stg.mcmc.gov.my.key
```

```yaml
# docker-compose.yml (dashboard host) — sketch, fill in image tags/secrets
services:
  traefik:
    image: traefik:v3
    command:
      - --providers.docker=true
      - --providers.file.filename=/etc/traefik/dynamic.yml
      - --entrypoints.websecure.address=:443
      - --api.dashboard=true
      - --entrypoints.traefik.address=:8081
    ports:
      - "443:443"
      - "127.0.0.1:8081:8081"   # Traefik's own admin dashboard — loopback only, not on :443/public
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - ./traefik/dynamic.yml:/etc/traefik/dynamic.yml:ro
      - /opt/certs:/certs:ro   # the org-issued cert/key for citadel-stg.mcmc.gov.my
    labels:
      - traefik.enable=true
      # Catch-all is safe here — this router only lives on the loopback-only
      # `traefik` entrypoint above, never on the public `websecure` one, so
      # it can't collide with the app's own /api router below.
      - traefik.http.routers.traefik-dashboard.rule=PathPrefix(`/`)
      - traefik.http.routers.traefik-dashboard.service=api@internal
      - traefik.http.routers.traefik-dashboard.entrypoints=traefik

  server:
    image: nssti-dev.mcmc.gov.my/nsrd/dns-compliance/server:main
    labels:
      - traefik.enable=true
      - traefik.http.routers.api.rule=Host(`citadel-stg.mcmc.gov.my`) && PathPrefix(`/api`)
      - traefik.http.routers.api.tls=true
      - traefik.http.routers.api.entrypoints=websecure
      - traefik.http.services.api.loadbalancer.server.port=8080
    volumes:
      - /opt/dns-compliance/certs:/certs:ro   # the private mTLS certs from above
    environment:
      TLS_CERT: /certs/server.crt
      TLS_KEY: /certs/server.key
      TLS_CA: /certs/ca.crt
      CRAWLER_ADDR: citadel-api.mcmc.gov.my:50052
      CRAWLER_TOKEN: "${CRAWLER_TOKEN}"
      DB_URL: "${DB_URL}"
      REDIS_ADDR: "${REDIS_ADDR}"
      MINIO_ENDPOINT: "${MINIO_ENDPOINT}"
      MINIO_ACCESS_KEY: "${MINIO_ACCESS_KEY}"
      MINIO_SECRET_KEY: "${MINIO_SECRET_KEY}"
    # No public ports — Traefik is the only thing that talks to :8080.
    # :50051 (gRPC, for the crawler's Submit calls) is exposed separately, not through Traefik.
    expose:
      - "8080"

  web:
    image: nginx:alpine   # or any static file server
    volumes:
      - ./web/dist:/usr/share/nginx/html:ro
    labels:
      - traefik.enable=true
      - traefik.http.routers.web.rule=Host(`citadel-stg.mcmc.gov.my`)
      - traefik.http.routers.web.tls=true
      - traefik.http.routers.web.entrypoints=websecure
      - traefik.http.services.web.loadbalancer.server.port=80
```

`web/dist/` comes from `npm --prefix web run build`, built and copied to the host (or baked into a small image) as a separate deploy step from the two Go binaries.

**Traefik's own dashboard** (`--api.dashboard=true`) is bound to `127.0.0.1:8081` — not the public `websecure` entrypoint — since it exposes internal router/service topology and isn't meant for public access. Reach it over SSH port-forwarding from the dashboard host:

```bash
ssh -L 8081:localhost:8081 user@192.168.88.46
# then open http://localhost:8081/dashboard/ locally
```

If it needs to be reachable without an SSH tunnel later, put it behind its own `Host()` rule on `websecure` with a `basicauth` middleware — don't expose `api@internal` on the public entrypoint unauthenticated.

Set `COOKIE_SECURE=true` (the server's default) — it requires the session cookie only be sent over HTTPS, which Traefik now provides. `:50051` still needs to be reachable directly by the crawler host (not through Traefik — see the mTLS section above), so open it on the host firewall independent of Traefik's `:443`.

**The crawler host (`citadel-api.mcmc.gov.my`) does not run Traefik.** It has no browser-facing HTTP surface — its only listener is the gRPC control service on `:50052`, reached exclusively by the dashboard's `Scanner`, already secured end-to-end by the mTLS setup above plus the shared token. Putting a reverse proxy in front would either do nothing (TCP passthrough) or break the link outright (if it terminates TLS, it becomes the gRPC client without a cert signed by the private CA, and `RequireAndVerifyClientCert` on the crawler's `grpc.NewServer` rejects it). The domain name is just what goes in `--grpc-addr`/`CRAWLER_ADDR` instead of the raw IP — not a public endpoint.

## Backing services (dashboard host only)

The crawler is stateless — no database, cache, or object storage. The dashboard needs:

- **PostgreSQL** — `DB_URL`
- **Redis** — `REDIS_ADDR` (notification queue)
- **MinIO/S3** — `MINIO_ENDPOINT`/`MINIO_ACCESS_KEY`/`MINIO_SECRET_KEY`/`MINIO_BUCKET`; the bucket needs a public-read policy (`docker-compose.yml`'s `minio-init` service runs `mc mb --ignore-existing local/screenshots && mc anonymous set public local/screenshots` — replicate manually if not reusing that compose service)

## First boot

`BOOTSTRAP_ADMIN_USERNAME`/`BOOTSTRAP_ADMIN_PASSWORD` env vars on the dashboard create the first admin user — but only if the `users` table is empty, so this is safe to leave set across redeploys (silent no-op once any user exists). Without it on a genuinely fresh database, no one can log in.

`--seed-dns` (baked into the server image's `ENTRYPOINT` as `/app/dns-server.yaml`) seeds the initial DNS server list only if that table is empty on first boot — the admin UI manages it from then on.

## Firewall summary

| Port | Host | Direction | Purpose |
|---|---|---|---|
| `443` | dashboard | inbound, public | Traefik → browsers/auditors |
| `8080` | dashboard | internal only (Traefik → server container) | REST API |
| `50051` | dashboard | inbound from crawler host | crawler's `Submit` RPC (results) |
| `50052` | crawler | inbound from dashboard host | dashboard's `StartSweep` RPC (trigger) |
| — | crawler | outbound, public internet | DNS resolution + Chrome navigating target sites |
