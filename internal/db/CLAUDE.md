# CLAUDE.md (internal/db/)

Database/models/store guidance for `internal/db/`. See the repo-root `CLAUDE.md` for the full-system architecture and `internal/server/CLAUDE.md` for the HTTP layer that calls into this package.

### Database (`internal/db/`)

- GORM with PostgreSQL driver (`gorm.io/driver/postgres`). SQLite driver (`glebarez/sqlite`) is also linked but PostgreSQL is the production path.
- Models: `DNSServer`, `URL`, `ScanRun`, `ScanResult`, `Department`, `User`, `Session`, `DepartmentURL`, `Agency`, `DomainWhois`, `IPInfo`, `Favicon`, `ScanSettings`, `ISPLogo`, `Instrument`, `Citation`, `Category`, `Element`, `URLOffence` (the last five are the legal citation catalog — see the legal-citation-catalog skill). `ScanSettings` is a single-row (`ID` 1) table holding the admin-configurable scan cadence in minutes (`IntervalMinutes`/`Enabled`) plus DNS worker concurrency (`DNSWorkers`, default 100, flows into `SweepRequest.dns_workers` — see `proto/compliance.proto`), plus `SLAIntervalMinutes`/`SLAStreakThreshold` for the second, SLA-tracking-only sweep cadence — see "Scheduler" in internal/server/CLAUDE.md. `User.IsDeptAdmin` (bool, mutually exclusive with `IsAdmin`) is the department-admin flag — see "Auth & RBAC" in internal/server/CLAUDE.md. `DNSServer` has a required `ISP` field (groups servers in the UI's `groupByISP()`; `not null;default:'Unknown'`) and an `Enabled bool` field (`not null;default:true`) mirroring `DepartmentURL.Enabled`'s pattern — `ListDNSServers` (admin UI, result attribution) returns every server regardless of `Enabled`, while `ListEnabledDNSServers` (what `Scanner.run` actually builds sweep requests from) filters to `enabled = true`; `SetDNSServerEnabled(ctx, id, enabled)` toggles it via `PATCH /api/dns-servers/{id}/enabled`, independent of the full-replace `UpdateDNSServer`. `ScanResult` foreign-keys to `ScanRun`, `DNSServer`, and `URL` (via `URLID`); `URLValue` is guaranteed equal to `urls.url` — `grpcServer.Submit` normalizes the crawler's raw URL before storing it (using the `CreateURL`-returned `u.URL` as authoritative on the ad-hoc/disabled-URL fallback path), and `db.BackfillURLValues` (see "Domain normalization & watchlists" in the repo-root CLAUDE.md) repairs any pre-existing diverged rows — because `URLValue` is the `GROUP BY`/join key for nearly every aggregate query in this package (`ispStats`, `resurfacedDomains`, the heatmap, trend, uptime), not merely a display convenience. `ScanResult` carries a composite index `idx_scan_results_url_server_time (url_value, dns_server_id, scanned_at)` — column order matters, don't reorder — plus standalone indexes on `dns_server_id` and `scanned_at`; the composite exists specifically to serve the `MAX(scanned_at) GROUP BY url_value, dns_server_id` latest-per-(domain,server) subqueries in `ispStats`/`resurfacedDomains`, which previously scanned the whole table on every ISP page load. `ScanResult.LatencyMs int64` (`default:0`) holds DNS round-trip latency in milliseconds, 0 when resolution failed or wasn't measured — captured end-to-end from `internal/dns` resolver return values through `pipeline.Result.LatencyMs` → the crawler's report entry (`proto/compliance.proto`'s `latency_ms` field) → `grpcServer.Submit`; surfaced in the ISP detail page's Avg/Min/Max Latency columns (see "ISP stats scoping" in internal/server/CLAUDE.md for how zero-latency rows are excluded from those aggregates). `ScanResult.ResolvedIPv6`/`ResolvedASN`/`ResolvedOrg`/`ResolvedNetName` hold the IPv6/ASN/org/NetName enrichment data (see "IP/ASN + WHOIS enrichment" below) — informational only, never affect `Compliant`. `User.DepartmentID` is non-nil for all users including admin (admin's department is created by migration). `DepartmentURL` is a composite-PK (`department_id`, `url_id`) join table with just an `Enabled bool` field and `CreatedAt` — no case metadata; `SetURLEnabled(ctx, deptID, urlID, enabled)` updates `Enabled` in place, and `ListWatchedURLs` only returns URLs where `enabled = true`, so disabling a URL silently excludes it from scans.

  **Case metadata (2026-08-20)** lives on `Case`, not `URL` — `URL` is purely domain identity now (`ID`, `URL`, `CreatedAt`). `Case` carries `DueDate *time.Time` (the SLA deadline used by time-to-compliance, see "ISP stats scoping" in internal/server/CLAUDE.md) and `RequestedAt *time.Time`. These moved off `URL` because a domain can carry many cases over its history (reblocked under a new reference) — a scalar column on `URL` could only ever hold the latest one. Status is **not** on `Case` — `CaseURL` carries its own `Status string` (server-validated against `requested`/`uplift`/`suspended`) and, since 2026-09-15, its own `AgencyID *uint` (FK to `Agency`, `OnDelete:SET NULL`, moved off `Case` for the identical reason) — since some urls within the same case reach a different outcome, and are handled by a different agency, than their siblings (a case genuinely covers many urls via one Notice, and each can be blocked/uplifted/suspended, and owned by an agency, independently). `CaseStore.UpdateCaseFields(ctx, deptID, caseID, fields)` applies a partial update to `Case`'s shared fields — `db.CaseFields{DueDate, RequestedAt}` (no `Status`, no `AgencyID` — moved to `CaseURL` 2026-09-15), `DueDate`/`RequestedAt` are double pointers (outer nil = don't touch, outer non-nil → nil inner = clear, outer non-nil → &v = set) — ownership (`deptID` owns `caseID`) is checked at the handler layer (`UpdateCase`, `internal/server/case_handlers.go`), same 404-not-403 pattern as `AddCaseLetter`/`AddCaseURL`, not inside the store method. `CaseStore.UpdateCaseURLStatus(ctx, caseID, urlID, status)` (PATCH `/api/cases/{id}/urls/{url_id}`) sets one (case, url) pair's own `CaseURL.Status` independently of any other url in the same case — `status` validated the same way (`internal/server/handlers.go`'s `urlStatusAllowed`); `CaseStore.UpdateCaseURLAgency(ctx, caseID, urlID uint, agencyID *uint) (bool, error)` (PATCH `/api/cases/{id}/urls/{url_id}/agency`) is the analogous per-(case,url) setter for `CaseURL.AgencyID`. `URLEntry` (the `ListDepartmentURLs`/`GET /api/urls` read shape) still exposes `due_date`/`agency_id`/`agency_name`/`status`/`requested_at`/`current_reference_number` under the same JSON names as before frontend compatibility, but every value is now derived from the url's **most-recently-created Case** (`ORDER BY cases.created_at DESC LIMIT 1`, correlated subquery — see `postgresStore.ListDepartmentURLs` in `postgres.go`) rather than stored directly, except `status`, which is that specific url's own `CaseURL.Status` within the latest case (a further correlated subquery on `case_urls`, keyed by `(latest_case.id, urls.id)`), and `agency_id`/`agency_name`, which likewise come from that same url's `CaseURL` row within the latest case (`case_urls`, moved off `Case` 2026-09-15) rather than from `Case` itself; a url with zero cases yields all of these as null/empty. `PATCH /api/urls/{id}` (`ToggleURL`) now accepts only `{"enabled"?: bool}` — case metadata edits go through `PATCH /api/cases/{id}` instead (see internal/server/CLAUDE.md). The old `URLCaseFields`/`UpdateURLCaseFields` (on `URLStore`) are gone; a backfill (`db.BackfillURLCaseMetadataIntoCases`, `internal/db/migrate.go`, invoked from `Connect` in `db.go` before the four old `urls` columns are dropped) moves any already-set legacy values into one `Case` per distinct watching department, same "log and skip, non-fatal" philosophy as `BackfillURLValues` for a url with zero watching departments. `db.CaseLetterFields` (partial update to a `CaseLetter`, `UpdateCaseLetterFields(ctx, caseID, letterID, fields)`, PATCH `/api/cases/{id}/letters/{letter_id}`) follows the same convention split as `CaseFields`: its string fields (`Subject`/`WorkflowStatus`/`ReferenceNumberExternal`/`ReferenceNumberInternal`/`Recipient`/`Requestor`/`Remarks`) are single pointers with present-but-empty-clears semantics, while its three date fields (`LetterDate`/`ReceivedAt`/`SubmittedAt`) are double pointers using `CaseFields.DueDate`'s convention (outer nil = don't touch, outer non-nil → nil inner = clear, outer non-nil → &v = set) since a date has no natural empty-string sentinel. `DeleteCaseLetter(ctx, caseID, letterID)` (DELETE `/api/cases/{id}/letters/{letter_id}`) removes one `CaseLetter` row, same `(caseID, letterID)` scoping as `UpdateCaseLetterFields` — no cascade to the case or its `case_urls` links. `db.CaseSummary`/`db.CaseSummaryDomain` are computed, non-persisted read structs (mirroring `CaseLetterEntry` above) backing `GET /api/case-summaries` — one row per case with its own fields, its Notice letter's fields (Notice chosen over Memo when both exist), and every domain it covers; `ListCases`/`ListCasesForDepartment` are their store-layer accessors (admin-global vs department-scoped, same split as `ListCaseLetters`/`ListCaseLettersForDepartment`).

  **Agency** (`db.Agency{ID, Name uniqueIndex, CreatedAt}`) is a small admin-managed lookup table, read open to any authenticated role (`GET /api/agencies`) and mutated by admin-or-department-admin (`POST`/`DELETE /api/admin/agencies[/{id}]`) — the same shared/global-catalog pattern as DNS servers/ISP logos/the legal citation catalog, not the stricter super-admin-only pattern `Department`/`CompliantIP` use. Managed from a dedicated "Agencies" tab on `/admin` (see the admin route bullet above).

  **DueDatePreset** (`db.DueDatePreset{ID, Label, Minutes, CreatedAt}`) is the admin/dept-admin-managed list of options in `urls.tsx`'s "Time to Block" duration picker (see the `urls.tsx` route bullet above) — same read-open/write-`requireAnyAdmin` shape as Agency, not department-scoped. Stored in minutes (not hours) so a preset can go down to single-digit minutes — useful for exercising due-date notifications without waiting hours for one to fire; the admin UI's Add dialog takes separate days/hours/minutes fields and combines them into one `minutes` value before submitting. `db.SeedDueDatePresets` (called from `main.go` alongside `SeedDepartments`/`SeedScanInterval`) seeds the original hardcoded 6h/24h/48h/72h/7-day options (in minutes) on first boot if the table is empty, so existing installs see the same choices they always did before this became configurable; after that, `urls.tsx`'s "Time-to-Block Durations" dialog (visible to `canManage` users only, alongside the "+ Add Domain" button) is authoritative. Purely a lookup table read at selection time — the picker computes `now + Minutes` into `due_date` client-side and never stores a reference back to the preset, so a preset can be deleted at any time without touching any URL's already-set `DueDate`. A pre-existing `hours` column is converted to `minutes` (×60) and dropped by a one-time migration in `db.Connect` (`internal/db/db.go`), since GORM's `AutoMigrate` only adds the new column, it never renames or backfills.
- `db.Store` (`internal/db/store.go`) decouples handlers and the gRPC server from the concrete implementation — tests can swap in a fake. It's composed by embedding fourteen aggregate-scoped sub-interfaces (`URLStore`, `DNSServerStore`, `ScanRunStore`, `ResultStore`, `ISPStatsStore`, `DepartmentStore`, `UserStore`, `SessionStore`, `CompliantIPStore`, `AgencyStore`, `ISPLogoStore`, `ScanSettingsStore`, `EnrichmentStore`, `LegalCitationStore`) rather than one flat method list — `postgresStore` (`internal/db/postgres.go`) implements all of them structurally, no explicit `implements` wiring needed. **When adding a function that only touches one aggregate, take that sub-interface as its parameter instead of the full `db.Store`** — it documents the dependency at a glance and narrows what a test double needs to implement; see `StartWhoisRefresher`/`fetchAndStoreWhois` (`db.EnrichmentStore`), `StartScheduler` (`db.ScanSettingsStore`), `fetchAndCacheIPInfo` (`db.EnrichmentStore`), and `requireAuth` (a small unexported `authStore` combining `db.SessionStore`+`db.UserStore` in `auth.go`) for the pattern. Multi-aggregate consumers (`Handlers`, `Scanner`) still take the full `db.Store`. Handler tests use `fullMockStore` (defined in `internal/server/handlers_test.go`) which implements all `Store` methods; copy this struct when adding new server tests — narrower sub-interface params can be satisfied by the same `fullMockStore` value (or a smaller purpose-built fake) without changes.
- **IP/ASN + WHOIS enrichment** (`internal/ipinfo/`, `internal/whois/`): informational data points that never affect the compliance verdict, which stays A-record-based.
  - `ScanResult.ResolvedIPv6` — AAAA-record lookup done alongside the A-record check (`internal/dns/resolver.go`'s `ResolveIPv6`/`NewResolverIPv6`/`NewDoTResolverIPv6`/`NewDoHResolverIPv6`, wired through `pipeline.Config.ResolveIPv6`); nil function = skip.
  - `ScanResult.ResolvedASN`/`ResolvedOrg`/`ResolvedNetName`/`ResolvedAbuseEmail` — the resolved IP's ASN + network operator via `ipinfo.Fetcher` (`internal/ipinfo/`, ipinfo.io; `--ipinfo-token` for the authenticated tier) plus NetName and abuse-contact email via a second RDAP IP-network lookup (`whois.FetchIP`, bootstraps to the correct RIR — ARIN/RIPE/APNIC/etc; `parseIPAbuseEmail` checks both a top-level `role="abuse"` entity and one nested a level down, since RIRs use both shapes). Both merge into the same `db.IPInfo` row keyed by IP (not domain, since an IP's ASN/NetName don't depend on which domain currently resolves to it) — fetched **at most once per distinct IP, ever** (no periodic refresh, and unlike `DomainWhois`/`SubdomainScan`, no per-domain refresh button either, since `IPInfo` isn't domain-scoped). `grpcServer.Submit` (`internal/server/grpc.go`) checks the cache first; on a miss it spawns a **detached goroutine** (`fetchAndCacheIPInfo`, takes both `ipinfo.Fetcher` and `whois.IPFetcher` — nil `netnameFetch` disables the NetName/abuse-email half) so slow/unreachable ipinfo.io or RDAP never blocks scan ingestion — that scan's row simply has zero ASN/Org/NetName/AbuseEmail until a later scan re-checks the now-warm cache. Because there's no backfill for already-cached IPs, adding a new field here (as `AbuseEmail` was) doesn't retroactively populate old rows — `POST /api/hosting/{ip}` (`RefreshHostingInfo`) exists specifically to force a re-fetch of an already-cached IP; `domain.$url.tsx`'s Domain Info refresh button calls both `RefreshDomainInfo` and this endpoint (for the domain's most recently resolved IP) together, and its `hosting` display value is `hostingOverride ?? hosting` — the override holding whatever `RefreshHostingInfo` last returned, since the underlying `ScanResult` rows freeze their `Resolved*` fields at insert time and won't reflect a manual cache refresh until a new scan runs.
  - `db.DomainWhois` caches RDAP registrar name/URL/abuse-contact email+phone plus creation/expiry dates per domain (`internal/whois/`, via `github.com/openrdap/rdap`), surfaced at `GET /api/domain/*url`. Abuse contact values that come back as `mailto:`/`tel:`-prefixed jCard URIs are stripped to plain text before storing (`parseDomain` in `whois.go`). Lazily fetched in a detached goroutine on watchlist-add (`fetchAndStoreWhois` in `handlers.go`, only if `whoisFetch` is non-nil), then kept warm by `server.StartWhoisRefresher` (`internal/server/whois_refresh.go`) — a background loop, separate from the scan `Scheduler`, that every `--whois-refresh-interval` (default 24h) re-fetches domains whose cached copy is older than `--whois-stale-days` (default 30), in batches of `whoisRefreshBatchSize` (20) with a fixed pause between fetches (`ponytail`-marked: sequential, no backoff/jitter — upgrade if RDAP 429s show up). A failed fetch is recorded in `FetchError` but leaves any previously-cached registrar/dates in place rather than wiping them.
  - `db.SubdomainScan` caches a `subfinder` (`internal/subfinder/`, shelled out to as a subprocess via `--subfinder-path`/`SUBFINDER_PATH`, github.com/projectdiscovery/subfinder) enumeration result per domain, surfaced at `GET /api/subdomains/*url`. Unlike `DomainWhois`, there's **no periodic refresh sweep** — `fetchAndStoreSubdomains` (`handlers.go`) runs once in a detached goroutine on watchlist-add (only if `subfinderFetch` is non-nil) and otherwise only ever re-runs from `RefreshSubdomains`, which blocks the request so the response reflects the fresh result immediately. A failed run is recorded in `FetchError` but leaves any previously-cached subdomain list in place.
- **Favicon caching** (`internal/favicon/`, `db.Favicon`, `GET /api/favicon/*url`): this app tracks domains under active enforcement, so a client-side favicon request (browser hitting the domain, or Google's favicon proxy, directly) would reveal an analyst's presence in the target's server logs. `FaviconByURL` (`internal/server/handlers.go`) fetches through the server instead and caches the raw image bytes in `db.Favicon` keyed by `urlnorm.Normalize`d domain (so `Example.com`/`example.com` share one cache row and one outbound fetch instead of two), **at most once per domain, ever** (no periodic refresh — mirrors the IPInfo/DomainWhois cache-once pattern above, but synchronous-on-miss rather than a detached goroutine, since the response body *is* the image). `favicon.Fetch` tries the domain's own `/favicon.ico` first, falling back to Google's `s2/favicons` proxy (which always returns *something*, including a generic placeholder for unknown domains) only if that fails. `web/src/api/domain.ts`'s `faviconApiUrl(domain)` builds the `<img src>` directly (not routed through `client.ts`, since the response is raw image bytes, not JSON) — used by `urls.tsx` and `domain.$url.tsx`. The live-typing `FaviconSearch` combobox (`web/src/components/unlumen-ui/favicon-search.tsx`, vendored from unlumen, used on `domain.index.tsx` and the `/urls` quick-add field) is the one deliberate exception: it hits Google's proxy client-side for search-as-you-type preview, before a domain is ever added to a watchlist.
- `db.Seed` populates `dns_servers` on first run from the YAML file passed via `--seed-dns` (skips if table is non-empty); `db.SeedDepartments` similarly seeds `CMOD`/`CRD` only if `departments` is empty; `db.SeedAdmin` creates the bootstrap admin only if `users` is empty (see "Auth & RBAC" in internal/server/CLAUDE.md).
- `PurgeURL`'s `DeleteURL` is a plain `Delete(&URL{}, id)` — dependent `ScanResult` and `DepartmentURL` rows are removed via `OnDelete:CASCADE` FK constraints, not application code. If you add another table that references `URL`, give it the same FK-level cascade rather than reintroducing manual cleanup. `RemoveFromWatchlist`, by contrast, deletes only the `DepartmentURL` row — it's the one path that's deliberately *not* a cascade. `DeleteDNSServer` is different: it manually deletes `ScanResult` rows in a transaction before deleting the server, because there is no FK-level `OnDelete:CASCADE` from `ScanResult` to `DNSServer` — if you add other tables referencing `DNSServer`, extend that transaction rather than adding a FK cascade.
- `grpcServer.Submit` resolves `URLID` by matching `ScanResult.URLValue` against `store.ListWatchedURLs()` in memory (`urlIDByValue` map), defensively re-normalizing via `urlnorm.Normalize` if the raw value isn't an exact match; on a miss (an ad-hoc "Scan Selected" URL, or one whose watchlist entry is disabled) it falls back to `store.CreateURL` (get-or-create by normalized value, same as `AddToWatchlist`) so every submitted result always resolves a valid, non-zero `URLID` rather than silently dropping the row.
- `DailyComplianceByURL(ctx, urlValue, since, until)` aggregates `ScanResult` rows server-side into one `DailyComplianceStat` per (DNS server, calendar day) — avoids shipping raw rows to the client just to bucket them for the heatmap. `DailyComplianceLevel(total, compliant)` (`internal/db/models.go`) buckets each day onto a 0-4 scale (0 = no scans, 1 = fully compliant, 2-4 = increasing violation share) — the frontend's `HEATMAP_LEVEL_COLORS` (`web/src/lib/heatmap-year.ts`) must stay in sync with this scale if it changes. All calendar-day bucketing in this package — the heatmap, `ispTrend`, `dailyTrend` (`NationalTrend`), and `serverUptime` — buckets `ScannedAt` (stored as a UTC instant) in `Asia/Kuala_Lumpur`, via a package-level `reportingLocation` in `postgres.go`, not UTC: this tool reports to a Malaysian regulator, so a scan at 07:00 MYT belongs on that Malaysian day, not the previous UTC one.
- **Resurfaced domains** (`resurfacedDomains` in `internal/db/postgres.go`, `GET /api/resurfaced` above): a domain "resurfaces" when its latest scan on a given DNS server is a violation but its prior scan on that same server was compliant — i.e. it was blocked, then came back. `db.ResurfacedDomain`/`db.ResurfacedServerEntry` (`internal/db/models.go`) are computed read-side structs, not persisted tables; `Store.ResurfacedDomains`/`ResurfacedDomainsForDepartment` live on `ISPStatsStore`. Surfaced as an Overview stat tile, an ISP-detail callout, and a scan-results badge (see the frontend routes above) — the highest-signal regression metric in the app, distinct from a domain that's simply never been compliant.
- **Domain summaries** (`GET /api/domains`, `GET /api/domains/*url` above): `db.DomainSummary`/`db.DomainServerSummary` (`internal/db/models.go`) are computed lifetime aggregates (total/compliant scan counts, last-scanned) per domain and per (domain, DNS server) — distinct from `/api/results`, which only reflects the latest `ScanRun`. `Store.ListDomainSummaries`/`ListDomainSummariesForDepartment`/`DomainServerSummaries` live on `ResultStore`. Backs `domain.index.tsx`'s browseable `DomainHistoryTable`.
- **ISP Logos** (`db.ISPLogo`, `internal/db/models.go`; `GET /api/isp-logos`, `POST`/`DELETE /api/admin/isp-logos` above): a real, persisted `ISPLogo{ISP string primaryKey, LogoURL string, CreatedAt}` table (unlike Resurfaced Domains/Domain Summaries above, which are computed on read) keyed by ISP name rather than FK'd to `DNSServer`, since one ISP name is shared across multiple `DNSServer` rows (e.g. an ISP's DoT and UDP servers) and a `DNSServer`-level field would need to be kept in sync across all of them. Deliberately **admin-supplied-URL only** — no upload endpoint, no server-side fetch/cache (unlike the favicon pipeline below), and no dead-link health-checking; an admin pastes a link to an already-hosted image (their own choice of host) and it's rendered directly via `<img src>` with `referrerPolicy="no-referrer"` (`isp-logo-chip.tsx`) so the browser doesn't leak this deployment's origin to that third-party host on every Overview page load. `Store.ListISPLogos`/`UpsertISPLogo`/`DeleteISPLogo` live on their own `ISPLogoStore` sub-interface (one aggregate, per the sub-interface convention above); `UpsertISPLogo` uses `clause.OnConflict` so re-adding an existing ISP overwrites its logo instead of erroring, with `CreatedAt` preserved across the overwrite. Managed exclusively from `/dns-servers` (visible to admin **and** department-admin, matching that page's other management controls) — click a card's `ISPLogoChip` to open `EditISPLogoDialog` when `canManage`; there is no separate list/"Add" dialog on `/admin` anymore (an earlier standalone "ISP Logos" section there was removed as redundant — see the `admin.tsx`+`admin.index.tsx` route bullet above). `UpsertISPLogo`'s get-or-overwrite-by-ISP-name semantics are unchanged by that removal. Renamed/deleted ISPs (via `PATCH`/`DELETE /api/dns-servers/{id}`) do **not** cascade to `ISPLogo` — a renamed ISP's old logo row is simply orphaned (the bento grid falls back to a monogram, and `/dns-servers`' own cards keep showing the stale name until manually cleaned up).
