# CLAUDE.md (internal/server/)

Server/HTTP/gRPC/auth guidance for `cmd/server` + `internal/server/`. See the repo-root `CLAUDE.md` for the full-system architecture (crawler, pipeline, database).

### Server (`cmd/server`, `internal/server/`)

- **HTTP** on `:8080` via [chi](https://github.com/go-chi/chi). All routes under `/api` except login require a valid session cookie (`requireAuth`); routes under `/api/admin/*` plus DNS server mutation additionally require `is_admin` (`requireAdmin`). See "Auth & RBAC" below.
  - `POST /api/auth/login` (public), `POST /api/auth/logout`, `GET /api/auth/me`
  - `GET /api/urls` — admin: every URL globally; non-admin: only their own department's watchlist (`ListDepartmentURLs`); returns `URLEntry[]` (includes `enabled` flag per department)
  - `POST /api/urls` (`AddToWatchlist`) — gets-or-creates the URL by normalized value and links it to the calling user's department watchlist; all roles (including admin) use their own `DepartmentID`
  - `PATCH /api/urls/{id}` — `enabled` stays department-scoped (only affects the caller's own watchlist entry); the other three fields are case metadata that lives on the shared `URL` row (see internal/db/CLAUDE.md) — editing them is visible to every department watching the domain, not siloed per department, though the caller's department must still be watching the URL to write at all (enforced by `UpdateURLCaseFields`, 404 otherwise, same as before). Body accepts `{ "enabled"?: bool, "due_date"?: string, "agency_id"?: number, "status"?: string, "requested_at"?: string }` and only touches fields present in the body. `enabled` toggles `DepartmentURL.Enabled` (`ListWatchedURLs` only includes enabled URLs, so disabling a URL removes it from future scans without deleting watchlist membership). `due_date` sets `URL.DueDate` — RFC3339 to set, `""` to clear — the SLA deadline (carries time-of-day) used by the time-to-compliance metric (see "ISP stats scoping" below). `agency_id` sets `URL.AgencyID` — a real ID (FK'd to the `Agency` lookup table, see "Case metadata" in internal/db/CLAUDE.md) rather than free text; `0` clears it (never a real row id, same clear-sentinel convention `due_date`'s `""` uses) — a bad/nonexistent id fails the FK constraint at the DB layer and surfaces as a 500, not a 400. `status` is server-validated against `requested`/`uplift`/`suspended` (400 on anything else, `""` clears it) and is independent of the derived `Compliant` field; `requested_at` is RFC3339/`""` like `due_date`. All case-metadata fields (beyond `enabled`) route through one combined store call, `db.Store.UpdateURLCaseFields` (renamed from `UpdateDepartmentURLFields`), rather than one setter per field. Reference numbers/requesting departments are no longer tracked here — see the `cases`/`case_letters`/`case_urls` routes below.
  - `DELETE /api/urls/{id}` (`RemoveFromWatchlist`) — unlinks the URL from the calling user's department watchlist only; never deletes the `URL` row or its `ScanResult` history. 404 if the URL wasn't actually on that watchlist.
  - `GET /api/urls/requested-count` (`URLsRequestedThisMonth`) — count of `DepartmentURL` rows (watchlist additions) created since the start of the current calendar month, not a rolling 30-day window; admin: global count (`CountDepartmentURLsSince`), non-admin: scoped to their own department (`CountDepartmentURLsSinceForDepartment`). Backs the Overview page's "URLs requested this month" stat.
  - `GET /api/dns-servers` — any authenticated role (results reference servers by name, so everyone needs to read this)
  - `GET /api/agencies` — any authenticated role; the Agency lookup table `urls.tsx`'s dropdown/filter reads from. Mutations (`POST`/`DELETE /api/admin/agencies[/{id}]`) are admin-or-department-admin, listed with the other `requireAnyAdmin` routes below.
  - `GET /api/due-date-presets` — any authenticated role; the list of "Time to Block" duration options `urls.tsx`'s picker reads from (see `db.DueDatePreset` in Database below). Mutations (`POST`/`DELETE /api/due-date-presets[/{id}]`) are admin-or-department-admin, listed with the other `requireAnyAdmin` routes below.
  - `GET /api/departments` (`ListDepartmentsOpen`) — any authenticated role; same underlying data as the existing super-admin-only `GET /api/admin/departments`, added specifically for the Requesting Dept. dropdown/filter any user needs — the admin-only route and its handler are untouched, this is a new, additive, separately-gated one.
  - `POST /api/dns-servers` — **admin or department-admin**; body requires `isp` (string, mandatory), `address`, and optionally `name`/`protocol`. DNS servers are one shared/global catalog, not department-scoped, so a department admin can add/edit/delete same as a super admin.
  - `PATCH /api/dns-servers/{id}` — **admin or department-admin**; same body shape as `POST`, full-replace (not partial) — `isp`/`address` required, `protocol` defaults to `udp` if omitted
  - `DELETE /api/dns-servers/{id}` — **admin or department-admin** (see above)
  - `PATCH /api/dns-servers/{id}/enabled` — **admin or department-admin**; body `{ "enabled": bool }`. Toggles `DNSServer.Enabled` without deleting the server or its history — a disabled server is skipped by `ListEnabledDNSServers` (what `Scanner.run` actually sweeps against) but still appears in `ListDNSServers` (admin UI, past-result attribution), so "stop monitoring this resolver" and "delete this resolver" are two different, non-destructive-vs-destructive actions. Surfaced as a `Switch` in each `dns-servers.tsx` bento card footer.
  - `GET /api/dns-servers/{id}/uptime` (`ServerUptime`) — daily up/down status for one specific DNS server over a `since`/`until` RFC3339 window (defaults to last 30 days); admin/department scoping matches `ISPTrend`. A day is `up: false` only when a majority of that day's scans against the server errored with a timeout/SERVFAIL (`db.isDownError`, mirroring `dns-error.ts`'s classification) — i.e. the resolver itself failed to respond, not merely a domain being blocked (a normal, non-error result). Rendered as a binary step-line sparkline (`TrendSparkline` with `mode="status"`) in each `dns-servers.tsx` bento card, distinct from `ISPTrend`'s percentage-based compliance trend.
  - `POST /api/dns-servers/test` (`TestDNSServer`) — any authenticated role; body `{ "address", "protocol" }`, resolves `example.com` against the given address/protocol with a 5s timeout and returns `{ "success": true, "ip", "latency_ms" }` or `{ "success": false, "error" }`. The address doesn't need to belong to an already-created `DNSServer` row — lets `dns-servers.tsx`'s Add/Edit dialog verify a candidate resolver before (or after) saving it.
  - `POST /api/scan`, `GET /api/scan/status` — trigger a DNS-only scan / poll status
  - `GET /api/scan/progress` — per-DNS-server result counts for the active scan run (polled by dashboard); `total_urls` reflects `ListWatchedURLs` (domains on at least one watchlist), not the global pool
  - `GET /api/scan/progress/stream` — SSE endpoint; server pushes the same `ScanProgressResponse` JSON whenever the `Broadcaster` publishes (crawler calls this implicitly via gRPC `Submit`)
  - `GET /api/results` — admin: global `LatestResults`; non-admin: `LatestResultsForDepartment`. Both return only rows from the most recent `ScanRun` (`store.LastScanRun`), not each URL/DNS-server pair's latest-ever result — a domain untouched by that run (e.g. disabled mid-sweep, or excluded from a targeted "Scan Selected" run) simply doesn't appear until a run that includes it completes, rather than lingering with a stale row.
  - `GET /api/results/*url`, `GET /api/heatmap/*url` — non-admin gets a 404 (not 403, to avoid confirming the domain exists) unless `URLOwnedByDepartment` passes; admin unscoped. `since`/`until` query params are RFC3339, defaulting to the last 7 days. Both handlers, plus `DomainServerSummaries`, resolve the `*url` wildcard via the shared `urlParamFromRequest(r)` helper (`handlers.go`) — unescapes then `urlnorm.Normalize`s, 400 on a normalize error — rather than matching the raw path segment against `url_value` directly; a mixed-case or scheme-prefixed request (e.g. `Example.com`) would otherwise silently return empty history with a 200 instead of a match, since `url_value` is stored normalized
  - `GET /api/dns-records/*url` — live DNS lookup, unscoped for any authenticated role (not watchlist data)
  - `GET /api/domain/*url` (`DomainInfoByURL`) — cached RDAP registrar/creation/expiry info for a domain, scoped like `/api/results` (404, not 403, for a non-owning department). Returns `{"fetched":false}` (not a 404) when the domain is owned but has no cached `DomainWhois` row yet
  - `GET /api/favicon/*url` (`FaviconByURL`) — server-cached favicon bytes for a domain, unscoped for any authenticated role (not watchlist data); see "Favicon caching" in internal/db/CLAUDE.md
  - `GET /api/subdomains/*url` (`SubdomainsByURL`) — cached `subfinder` enumeration result for a domain, scoped like `/api/results`. Returns `{"fetched":false}` when the domain is owned but has no cached `SubdomainScan` row yet (never scanned, or `--subfinder-path` is empty/disabled)
  - `POST /api/subdomains/*url` (`RefreshSubdomains`) — on-demand re-run of subdomain enumeration, blocking until it completes; the only way a cached row is ever updated after the initial on-watchlist-add fetch (no periodic sweep, unlike WHOIS)
  - `POST /api/hosting/{ip}` (`RefreshHostingInfo`) — on-demand ASN/org/NetName/abuse-email re-fetch for a resolved IP, bypassing `IPInfo`'s fetch-once-ever cache; unscoped for any authenticated role (`IPInfo` is keyed by IP, not department-owned watchlist data). Returns 503 if `--ipinfo-token`'s fetcher isn't wired (mirrors the other on-demand-fetch 503s)
  - `POST /api/screenshot` — trigger a single-URL screenshot scan against one or more DNS servers (`dns_server_ids`), unscoped for any authenticated role; the crawler resolves each server then captures all resulting (url, IP) pairs concurrently through its screenshot worker pool (see `captureResolved` in `cmd/crawler/main.go`), so requesting N servers isn't N times slower than one
  - `GET /api/legal/instruments`, `GET /api/legal/instruments/{id}/citations`, `GET /api/legal/citations/{id}/categories`, `GET /api/legal/categories/{id}/elements`, `GET /api/legal/elements/{id}/subelements` — any authenticated role (shared/global reference data, same read-open shape as DNS servers/ISP logos; mutations live in the admin-gated group below) — see the legal-citation-catalog skill
  - `GET /api/legal/offences/*url` (`OffencesByURL`), `POST /api/legal/offences/*url` (`AttachOffence`), `DELETE /api/legal/offences/{id}` (`DetachOffence`) — department-ownership-scoped like `/api/results` via `requireDomainOwnership` (the same 404-not-403 helper), not global like the catalog routes above; `DetachOffence` is keyed by the offence's own surrogate ID, resolving ownership via its preloaded `URL`
  - `GET /api/cases/*url` (`CasesByURL`), `POST /api/cases/*url` (`CreateCaseForURL`) — department-ownership-scoped like the offence routes above via `requireDomainOwnership`, not admin-gated (same `requireAuth` group as the offence routes). `CreateCaseForURL`'s `department_id` is always the caller's own `user.DepartmentID`, never client-supplied; body is `{ "phase": "requested" | "uplift" | "suspended" }`. `POST /api/cases/{id}/letters` (`AddCaseLetter`) is keyed by the case's own surrogate ID (not the URL) and is scoped differently — ownership is resolved via `db.Store.GetCase`'s `DepartmentID`, not URL watchlist membership, since a case belongs to exactly one requesting department regardless of how many other departments independently watch its URL(s) (unlike `DetachOffence`'s URL-based ownership, which is correct there because offences are shared/global catalog data attached to a URL, not per-department case data); body mirrors `db.CaseLetter`'s fields (`type` required, the rest optional). See `internal/db/CLAUDE.md`'s Case/CaseLetter/CaseURL model docs for the full schema.
  - `GET /api/isps/{isp}` (`ISPStats`) — per-DNS-server compliance + latency aggregates for one ISP, plus its most-violated domain; admin: global `store.ISPStats`; non-admin: `ISPStatsForDepartment`, scoped to their department's enabled watchlist (see "ISP stats scoping" below)
  - `GET /api/isps/{isp}/trend` (`ISPTrend`) — daily compliance counts for one ISP over a `since`/`until` RFC3339 window (defaults to last 30 days); same admin/department scoping as `ISPStats`
  - `GET /api/isps/{isp}/timing` (`ISPTiming`) — time-to-compliance for one ISP: median/avg days from a domain's `URL.DueDate` to its first compliant scan by that ISP, plus blocked/still-open/coverage counts and a top-5 "slowest to block" list; same admin/department scoping as `ISPStats`. Domains with no `DueDate` are excluded, not defaulted to some other date — see "ISP stats scoping" below
  - `GET /api/trend` (`NationalTrend`) — daily compliance counts aggregated across **all** ISPs (same shape as `ISPTrend`, no `isp` filter); same admin/department scoping, backs the Overview page's national trend chart
  - `GET /api/resurfaced` (`ResurfacedDomains`) — domains whose most recent scan flipped compliant→violating on at least one DNS server (a regression signal, distinct from a domain that's simply never been compliant); admin: global `store.ResurfacedDomains`; non-admin: `ResurfacedDomainsForDepartment`. Returns `[]db.ResurfacedDomain`, each carrying the affected servers and their flip timestamps (`db.ResurfacedServerEntry`) — see "Resurfaced domains" in internal/db/CLAUDE.md
  - `GET /api/domains` (`DomainSummaries`) — paginated (`page`/`page_size`, default 25, max 100) lifetime-aggregate summary per domain (total scans, compliant scans, last-scanned) across **all** scan history, not just the latest run — distinct from `/api/results`. Admin: `ListDomainSummaries`; non-admin: `ListDomainSummariesForDepartment`. Backs `domain.index.tsx`'s `DomainHistoryTable`
  - `GET /api/domains/*url` (`DomainServerSummaries`) — per-DNS-server lifetime aggregate for one domain (the expanded-row breakdown under `DomainHistoryTable`), scoped like `/api/results` (404 for a non-owning department)
  - `GET /api/isp-logos` (`ListISPLogos`) — any authenticated role (the bento grid needs it for every user, not just admins); returns `[]db.ISPLogo`
  - `POST /api/admin/isp-logos` (`UpsertISPLogo`) — **admin or department-admin**; body `{ "isp": string, "logo_url": string }`, both required; get-or-overwrite by ISP name (re-adding an existing ISP replaces its logo rather than erroring)
  - `DELETE /api/admin/isp-logos/*` (`DeleteISPLogo`) — **admin or department-admin**; wildcard route (not `{isp}`) so ISP names containing spaces/special characters round-trip correctly, same pattern as the `*url` routes
  - `POST /api/admin/agencies` (`CreateAgency`), `PATCH /api/admin/agencies/{id}` (`UpdateAgency`, body `{ "name" }`), `DELETE /api/admin/agencies/{id}` (`DeleteAgency`) — **admin or department-admin**, same `requireAnyAdmin` group as DNS servers/ISP logos/the legal catalog (a deliberate deviation from the stricter super-admin-only `Department`/`CompliantIP` pattern — see "Agency" in Database below). `URL.AgencyID` is `OnDelete:SET NULL`, so deleting an Agency in use clears the reference on any URL that had it rather than erroring or cascading.
  - `POST /api/due-date-presets` (`CreateDueDatePreset`, body `{ "label", "minutes" }`, both required and `minutes` must be positive), `DELETE /api/due-date-presets/{id}` (`DeleteDueDatePreset`) — **admin or department-admin**, same `requireAnyAdmin` group as Agency above. No FK from anything back to `DueDatePreset` — a preset is only ever read at selection time to compute `now + minutes`, so deleting one doesn't touch any already-set `URL.DueDate`.
  - `POST/PATCH/DELETE` on `/api/legal/instruments[/{id}]`, `/api/legal/citations[/{id}]`, `/api/legal/categories[/{id}]`, `/api/legal/elements[/{id}]`, plus `POST /api/legal/citations/parse-preview` (runs `internal/legalcite.Parse` without persisting, for a live preview in the add-citation form) — all **admin or department-admin**, same rationale as DNS servers (shared/global catalog, not department-scoped) — see the legal-citation-catalog skill
  - `GET/POST /api/admin/users`, `DELETE /api/admin/users/{id}` — **admin or department-admin**; a department admin only sees/creates/deletes plain members of their own department (server forces `DepartmentID`/no elevated role regardless of request body — see "Auth & RBAC" below); a super admin can additionally grant `is_admin`/`is_dept_admin` and pick any department
  - `POST /api/admin/users/{id}/reset-password` (`ResetUserPassword`) — **admin or department-admin**, same dept-own-plain-member scoping as `DeleteUser`; generates a random temporary password (`generateTempPassword`, `crypto/rand`), sets `User.MustChangePassword`, and returns `{ "temp_password": string }` — the only place the plaintext is ever surfaced, so the admin must hand it off out of band immediately. The target is forced through `POST /api/auth/change-password` before using the app again (see `RootLayout`'s gate in `web/CLAUDE.md`).
  - `POST /api/auth/change-password` (`ChangePassword`) — any authenticated role, self-service only; body `{ "current_password", "new_password" }`, verifies the current password first, clears `MustChangePassword`. This is also how a user completes an admin-initiated reset.
  - `GET/POST /api/admin/departments`, `PATCH /api/admin/departments/{id}` (`UpdateDepartment`, body `{ "name" }`) — **admin-only** (cross-department by nature)
  - `PATCH /api/admin/users/{id}` (`UpdateUser`, body `{ "username", "is_admin", "is_dept_admin", "department_id" }`, full-replace) — **admin-only** (routed under the super-admin-only group, not `requireAnyAdmin` — unlike Create/Delete/reset-password, a department admin cannot edit any user, including their own department's)
  - `GET/POST /api/admin/compliant-ips`, `DELETE /api/admin/compliant-ips/{id}` — **admin-only**; manages the `db.CompliantIP` list consumed by the crawler's `--compliant-ips` flag (see "Domain semantics" in the repo-root CLAUDE.md)
  - `GET /api/admin/urls/unassigned` — **admin-only**: URLs with zero `DepartmentURL` links (pre-migration legacy rows, or domains every department has since removed)
  - `DELETE /api/admin/urls/{id}` (`PurgeURL`) — **admin-only** hard delete; cascades to `ScanResult` and `DepartmentURL` via FK. The only way to actually destroy scan history — `RemoveFromWatchlist` never does.
  - `GET/PATCH /api/admin/scan-interval` — **admin-only**; reads/writes the single-row `db.ScanSettings` (see "Scheduler" below) that controls the automated scan cadence (`interval_minutes`, `enabled`) and DNS worker concurrency (`dns_workers`), plus the SLA-tracking cadence (`sla_interval_minutes`, `sla_streak_threshold`); a successful `PATCH` also calls `Scanner.NotifyScheduleChanged` so changed settings take effect immediately (both schedulers) instead of after their previous wait finishes
- **gRPC** on `:50051` — receives `ComplianceReport` submissions from the crawler; uploads any screenshot bytes to MinIO, stores results in PostgreSQL, then calls `broadcaster.Publish` so all SSE subscribers receive the updated progress. Authenticated by the shared `--crawler-token`/`--auth-token` secret (empty token disables the check and logs a startup warning) — runs on the trusted crawler↔server link, not the public API; see "gRPC" section below for the full mTLS + auth picture.
- **Broadcaster** (`broadcaster.go`) — in-memory fan-out pub/sub for SSE. `Subscribe()` returns a buffered `chan []byte`; slow consumers are silently dropped via a non-blocking `select`. Wired into `Handlers` and called from `grpcServer.Submit` after each batch insert.
- **Scanner** (`scanner.go`) — triggers sweeps on the crawler's persistent control service over gRPC (`CrawlerControl.StartSweep`, auth-gated by a shared `--crawler-token`/`--auth-token`), with a mutex-guarded `running` flag. `Trigger(ctx, reason, urls []string)` does a DNS-only crawl against the provided URL list, or against `store.ListWatchedURLs(ctx)` (enabled-only) when `urls` is `nil`. `TriggerScreenshot` sets `Screenshots: true` on the request and targets a single URL + DNS server. Both set `SweepRequest.DnsWorkers` from `store.GetDNSWorkers` (via the unexported `dnsWorkers` helper, which returns 0 — non-fatal, crawler falls back to its own `--dns-workers` CLI default — on a read failure); `cmd/crawler/control.go`'s `StartSweep` only overrides `cfg.DNSWorkers` when the field is `> 0`. `NotifyScheduleChanged` sends (non-blockingly) on a buffered `scheduleReset` channel that `StartScheduler`'s loop also selects on — see "Scheduler" below; nil-safe since some tests construct routes with a nil `*Scanner`. `StartSweep` is a blocking call — it returns only once the crawler has finished the sweep — so `Scanner` waits on it the same way it used to wait on the old `exec.Command` subprocess exiting, and `CompleteScanRun`/broadcaster bookkeeping is unchanged. This is what lets the crawler and dashboard run on separate hosts — see `docs/superpowers/specs/2026-07-22-split-crawler-dashboard-hosts-design.md`.
- **Scheduler** (`scheduler.go`) — two independent background loops, both started from `main.go`, both gated by the same `ScanSettings.Enabled` flag (**defaults to false** — automated scanning is an explicit admin opt-in) and both restarted immediately on an admin settings save via `Scanner.NotifyScheduleChanged` (see below).
  - `StartScheduler(ctx, sc, store, defaultInterval)` calls `scanner.Trigger(ctx, "scheduled", urls)` on a cadence read fresh from `store.GetScanInterval` before every wait (`defaultInterval`, from `--interval` default 60, is only a fallback if the setting can't be read). `urls` is the watchlist *minus* whatever `StartSLAScheduler` is currently covering (`watchedURLsExcludingSLAActive`), not `nil` — so a URL under active SLA tracking isn't swept twice in the same round; if that leaves nothing to scan, the sweep is skipped entirely (an empty slice, unlike `nil`, would make `Scanner.run` fall back to scanning everything). `store.GetScanEnabled` is checked right before each trigger — disabling the schedule (the admin UI's `Switch`) skips that sweep without stopping the loop; a read error fails open (treated as enabled). Watches `sc.scheduleReset`.
  - `StartSLAScheduler(ctx, sc, store, defaultInterval)` — structurally identical, but sweeps only `store.SLAActiveURLs(ctx, streakThreshold)` (watched URLs with a past `DueDate` where at least one *enabled* `DNSServer` hasn't yet reached `SLAStreakThreshold` consecutive compliant scans for that `(url, server)` pair — tracked independently per server, so a URL stays active until every enabled server individually qualifies; a URL that later resurfaces after graduating is **not** re-escalated back onto this cadence, that's `GET /api/resurfaced`'s job instead) on a cadence read from `store.GetSLAInterval` (`--sla-interval`, default 15 — deliberately shorter than the normal interval, so `ispComplianceTiming`'s time-to-compliance measurement has finer granularity for domains actually under SLA). `SLAActiveURLs` (`internal/db/postgres.go`) finds each `(url_value, dns_server_id)` pair's most recent `SLAStreakThreshold` scans via a correlated `COUNT` subquery rather than a window function (same SQLite-test-driver portability reasoning as `resurfacedDomains`). Triggers tag their `ScanRun` `"scheduled-sla"`. Watches its own `sc.slaScheduleReset` — a single shared reset channel would only wake one of the two loops per signal, so `Scanner` carries two.
  - `db.SeedScanInterval` creates the single `ScanSettings` row (ID 1) from `--interval`/`--sla-interval`/`--sla-streak-threshold` on first boot only (`DNSWorkers` seeded to 100) — after that the admin panel (`GET/PATCH /api/admin/scan-interval`) is authoritative for all five fields (the UI's interval sliders range 1-512).
- Server flags accept env-var fallbacks: `DB_URL`, `MINIO_ENDPOINT`, `MINIO_ACCESS_KEY`, `MINIO_SECRET_KEY`, `MINIO_BUCKET`, `CRAWLER_ADDR`, `CRAWLER_TOKEN`, `COOKIE_SECURE`, `BOOTSTRAP_ADMIN_USERNAME`, `BOOTSTRAP_ADMIN_PASSWORD`, `TLS_CERT`, `TLS_KEY`, `TLS_CA`, `REDIS_ADDR`.

### Auth & RBAC (`internal/server/auth.go`, `auth_handlers.go`, `admin_handlers.go`, `internal/db/auth.go`)

- **Session-cookie auth**, not JWT: `POST /api/auth/login` checks `db.CheckPassword` (bcrypt, via `golang.org/x/crypto/bcrypt`) against `User.PasswordHash`, then creates a random-token `Session` row (`db.HashPassword`/`CheckPassword` live in `internal/db` so both the login handler and `db.SeedAdmin` share one implementation) and sets an HTTP-only, `SameSite=Lax` cookie (`session_token`). `--cookie-secure` controls the `Secure` flag — set `false` for local plain-HTTP dev, since Vite's proxy talks over plain HTTP.
- `requireAuth(store)` middleware (`auth.go`) resolves the cookie → `Session` → `User` and attaches the full `*db.User` to the request context (`userFromContext`); 401s if the cookie is missing, the session doesn't exist, or it's expired (`GetSession` filters `expires_at > now`). `GetSession` filtering expired rows doesn't delete them, so `server.StartSessionCleanup` (`internal/server/session_cleanup.go`, started from `main.go`) sweeps expired `Session` rows hourly (`db.SessionStore.DeleteExpiredSessions`) to keep the table from growing without bound — bounded-growth housekeeping, not a security control, since expired sessions were already unusable. `requireAdmin` must run after it and 403s unless `user.IsAdmin` (super admin only — for routes that are inherently cross-department, e.g. departments, compliant IPs, scan interval, URL purge). `requireAnyAdmin` 403s unless `user.IsAdmin || user.IsDeptAdmin` — used for routes a department admin should also reach (DNS servers, user management); handlers behind it that must further restrict a department admin to their own department do so themselves via `userFromContext` (see `CreateUser`/`DeleteUser`/`ListUsers` in `admin_handlers.go`).
- **Four roles for now**: `IsAdmin` (super admin, boolean flag on `User`) sees/manages everything globally and has its own "Admin" department (created by the admin migration in `internal/db/migrate.go`). `IsDeptAdmin` (boolean flag, mutually exclusive with `IsAdmin` — enforced in `CreateUser`) scopes the same kind of management capability (user CRUD, DNS server CRUD) to the user's own `DepartmentID` instead of globally; a department admin creating a user always gets a plain member of their own department regardless of what the request body asks for (the server overwrites `IsAdmin`/`IsDeptAdmin`/`DepartmentID`), and can only delete/list users within that same department. Neither flag set is a plain department member (watchlist-only). `CMOD`/`CRD` are real rows in the `departments` table (seeded by `db.SeedDepartments`, only if the table is empty) — more departments can be added later by inserting rows, no schema or code change needed.
- **Bootstrap admin**: `db.SeedAdmin(gormDB, username, password)` creates the first admin user only if `users` is empty, using `--bootstrap-admin-username`/`--bootstrap-admin-password`. Without this on a fresh deployment, no one could ever log in. Re-running with different flags is a silent no-op once any user exists.
- **Account creation is admin-provisioned only** — no self-registration. Admin sets a username + temporary password directly via the `/admin` UI (`POST /api/admin/users`). A forgotten/compromised password instead goes through `POST /api/admin/users/{id}/reset-password` (see above) — there's still no email-based flow, the temp password is handed off out of band and the recipient is forced to replace it via `POST /api/auth/change-password` on next login (`User.MustChangePassword`, checked client-side by `RootLayout` — see `web/CLAUDE.md`).
- **ISP stats scoping** (`internal/db/postgres.go`, `ISPStats`/`ISPTrend`/`ISPTiming`/`NationalTrend` handlers in `internal/server/handlers.go`): follows the same admin-global / non-admin-department-scoped pattern as `/api/results`. Admins get `store.ISPStats`/`ISPTrend`/`ISPComplianceTiming`/`NationalTrend` (unscoped); non-admins (403 if `user.DepartmentID` is nil) get the `*ForDepartment` variant, which joins `department_urls` filtered to `department_id = ? AND enabled = true` — so non-admins only see ISP aggregates over their own department's enabled watchlist domains. Latency aggregates (`AVG`/`MIN`/`MAX` of `latency_ms`) exclude zero-latency rows (`CASE WHEN latency_ms > 0 THEN latency_ms END`), since 0 means "no measurement" (compliant/failed-DNS rows), not an instant response.
- **Time-to-compliance** (`ispComplianceTiming` in `internal/db/postgres.go`): `URL.DueDate` is an optional, nullable SLA deadline — one value per domain (case metadata is global on `URL`, not per-department; see "Case metadata" in internal/db/CLAUDE.md), settable at add-time or later via `PATCH /api/urls/{id}`, never inferred from `CreatedAt`. For a given ISP, a domain's "days to block" is its first compliant scan by that ISP's servers minus `DueDate`, clamped to 0 if the compliant scan predates the deadline (already-blocked-before-due, not a negative duration). Domains with no `DueDate` are excluded from the aggregate entirely — `WithDueDateCount`/`TotalDomains` in the response exists so the UI can show real coverage instead of silently blending in a proxy date. Department scope still narrows *which* domains count toward the aggregate (joined through that department's `DepartmentURL` rows) — it's the pool, not the `DueDate` value itself, that's department-scoped; since `DueDate` is now a single global value per URL, the earlier per-department min-reduction this function used to do is gone entirely.
