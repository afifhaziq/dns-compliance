# CLAUDE.md (web/)

Frontend-specific guidance for `web/`. See the repo-root `CLAUDE.md` for architecture, backend routes, and database context this frontend talks to.

## Commands

```bash
cd web && npm install    # first time or after package.json changes

npm run dev        # dev server, hot reload, proxies /api to localhost:8080 — serves on :5173
npm run build       # production build → web/dist/
npm run lint        # ESLint only; type-check runs as part of build (tsc --noEmit)
npm run preview     # serve production build locally
```

For full-stack dev, run the Go server (`go run ./cmd/server/ ...`) alongside `npm run dev` — Vite proxies all `/api` requests to `localhost:8080`, so both must be running.

## Stack

- React 19 + TypeScript + Vite. **TanStack Router**, file-based (`web/src/routes/`) — add a file and the route is auto-discovered; `web/src/routeTree.gen.ts` is generated by the Vite plugin, never hand-edit it.
- `@` alias resolves to `web/src/` (`vite.config.ts`).
- Theming: `next-themes` (`attribute="class"`, `defaultTheme="light"`), toggled from the navbar by `theme-switch.tsx`; dark styles live alongside light ones in `index.css` under `html.dark`.
- Scan state (polling, refresh signal) lives in a React context in `__root.tsx`, consumed via `useScan()`.

## Auth (`web/src/routes/__root.tsx`)

`AuthContext`/`useAuth()` (hydrated via `fetchMe()` on mount) gates `RootLayout`: no session → redirect to `/login`; logged in on `/login` → redirect to `/`. `fetchMe` resolves to `null` on 401 instead of throwing (`skipAuthRedirect`), so the layout's own check can't cause a redirect loop; `client.ts` redirects any *other* 401 to `/login` unless a call opts out with `{ skipAuthRedirect: true }`. The navbar's "Scan Selected" flow (`ScanSelectedDialog`) snapshots current results into `sessionStorage` (`scan-baseline-${triggeredAt}`) before triggering, so `/scan-results` can diff against that baseline to compute newly-violating domains. `normalizeForClient()` (defined here) is a JS mirror of Go's `urlnorm.Normalize`, used for ad-hoc URL entry.

## API layer (`web/src/api/`)

One module per resource, all calling through `client.ts` (thin `fetch` wrapper: `credentials: 'same-origin'`, 401 handling, `api.patch()`). Which function calls which route is documented once, in `internal/server/CLAUDE.md`'s route list — read the relevant `web/src/api/*.ts` file directly rather than expecting a second copy here. One real gotcha, not visible from either side alone: every fetcher expecting an array response guards with `Array.isArray(data) ? data : []` — Go marshals a nil slice (e.g. an empty table, no scans run yet) to JSON `null`, not `[]`, which crashes a bare `.map()`/`.filter()` on the response.

## Routes (`web/src/routes/`)

Non-obvious behavior per route — everything else (which components render, which props they take) is one file open away.

- `index.tsx` (`/`) — Overview: national summary stats, a "Resurfaced" count via `fetchResurfacedDomains()` styled as a violation whenever >0, a 30-day trend chart (only shown once ≥2 data points exist), and `ISPBentoGrid` (worst-compliance-first gauge tiles, replacing the older `ISPStatusTable`). No per-DNS-server breakdown here — that granularity lives on the ISP detail page.
- `urls.tsx` (`/urls`, navbar label "Watchlist") — Due Date ("Time to Block") is a `<Select>` of duration options ("24 hours"), not a calendar picker — case owners think in SLA duration ("the ISP has 24h"), not calendar dates; picking a duration computes `now + minutes` client-side and stores that as the actual `due_date` timestamp. The duration list itself is admin/dept-admin-configurable (`DueDatePreset`, "Time-to-Block Durations" dialog) rather than hardcoded — stored in minutes rather than hours specifically so a preset can be a couple of minutes long, for testing due-date notifications without waiting. All field edits commit through one combined `PATCH /api/urls/{id}` (`setUrlFields`) with optimistic updates that roll back on failure; text fields commit on blur, not per keystroke. Search + filters apply client-side via one `useMemo`, not TanStack's built-in global filter. Row remove (`DELETE /api/urls/{id}`) is watchlist-scoped only and open to every role — the destructive admin hard-delete/"purge" lives solely in `/admin`. `MultiOffencePicker` stages offences via an explicit "+ Add offence" click and exposes an imperative `flush()` so a selection that's filled in but never clicked-to-add isn't silently dropped when a dialog closes. `AddUrlDialog` applies its whole staged offence/case-metadata set to every domain in the batch, not per-domain; the per-row `EditOffencesDialog`, by contrast, applies each change immediately (no batch-submit step, since the domain already exists).
- `dns-servers.tsx` (`/dns-servers`) — viewable by anyone, but add/edit/delete requires `is_admin`/`is_dept_admin` (403 server-side otherwise — DNS servers are a shared/global catalog, not department-scoped). One `.bento-card` per DNS server. The status badge animates Disabled→Syncing→Active on enable and jumps straight back to Disabled on disable. The enable/disable switch pauses future scans against that server (via `ListEnabledDNSServers`) without deleting it or its history — distinct from the destructive delete button beside it. The "Test" button (`testDnsServer`) resolves `example.com` against a candidate address/protocol before or after saving — works even on an address that isn't yet a saved `DNSServer` row.
- `results.index.tsx` (`/results`) — per-DNS-server subrows via `meta.expandedContent`. The domain-cell link is built from `hostname`, not the raw `url` field, specifically so a row with a legacy scheme-prefixed value can't double-prefix into `https://https://…`.
- `domain.index.tsx` (`/domain`) — the `FaviconSearch` combobox isn't backed by a known-domains list, so it accepts any hostname, not just ones with existing scan history. "Recent searches" is per-user, `localStorage`-only (`recent-searches-${userId}`, capped at 10) — entirely client-side, no server endpoint. `DomainHistoryTable` is a paginated *lifetime-aggregate* view, distinct from `/results`' latest-run-only view.
- `domain.$url.tsx` (`/domain/$url`) — Overview/History tabs default from the `?tab=` search param, so `/results`' history icon can deep-link straight into History. `DomainInfoPanel`'s single refresh button calls `RefreshDomainInfo` *and* the hosting refresh together, since `IPInfo`'s NetName/AbuseEmail are fetch-once-ever and won't otherwise update without a new scan. The Subdomains panel uses the virtualized `Table` rather than pagination, since a `subfinder` run can return hundreds of rows.
- `isps.$isp.tsx` (`/isps/$isp`) — latency columns show `—` when `avg_latency_ms` is 0, i.e. no measurement (not an instant response).
- `scan-results.tsx` (`/scan-results`) — reached only from the "Scan Selected" flow, not "Scan All". Diffs live results against the `sessionStorage` baseline (see Auth above) to compute newly-violating domains, and cross-references `fetchResurfacedDomains()` against the scanned set to badge resurfaced domains.
- `admin.index.tsx` (`/admin`) — 5 tabs; Departments/IP/Scan Settings stay super-admin-only (`RestrictedTabNotice` for a department admin), Users/Agencies work for both roles. The active tab is a *controlled* `?tab=` param (not `defaultValue`-only) so a refresh or shared link preserves it. A department admin's own "Create User" has no role picker at all — the server always creates a plain member of their own department regardless of role.
- `legal-citations.tsx` — see the `legal-citation-catalog` skill.

## UI components (`web/src/components/`)

Mostly self-describing on open; these are the non-obvious choices behind a few of them:

- `ui/table.tsx` — use its `Table`/`TableHeader`/`TableBody`/`TableRow`/`TableHead`/`TableCell` exports instead of raw `<table>` in any new table UI.
- `isp-logo-chip.tsx` — normalizes admin-supplied logos of mismatched aspect ratio into a uniform chip, falling back to a first-letter monogram when `logoUrl` is unset *or* the image fails to load (`onError`, since an admin-supplied URL can go dead). Loads with `referrerPolicy="no-referrer"` so the third-party logo host can't see this deployment's origin.
- `charts/` — `LiveLineChart` drives the real-time scan-progress chart on `results.index.tsx`; the static `LineChart`/`Line` primitives render the national/ISP trend sparklines. LTTB downsampling (`decimate-time-series`) is wired into the shared `time-series-chart-shell.tsx`, so every `LineChart` gets it automatically.
- `motion/table/` — a virtualized data table (`@tanstack/react-virtual`, column reorder/resize/sort, row selection, editable cells) — not yet wired into any route as of this writing.
- `reui/` — vendored `data-grid`/`filters` table primitive (distinct from `motion/table` above), currently backs `domain.index.tsx`'s `DomainHistoryTable`.

Use `cn()` from `web/src/lib/utils.ts` for conditional class composition. Icons: `lucide-react`. Animation: `motion` (Framer Motion).
